## 2. 技术选型

### 推荐：wxPython + matplotlib（已装，走桌面应用）

| 项 | 说明 |
|---|---|
| GUI 框架 | **wxPython 4.2.3**（项目 `pyproject.toml` 里已有可选依赖 `gui`，重构前的 `gui.py` 也是 wx） |
| 图表 | matplotlib（Agg 之外用 `FigureCanvasWxAgg` 嵌入），K 线用 mplfinance |
| 表格 | `wx.grid.Grid`（虚拟表模式支持万行级滚动） |
| 线程 | 长任务（选股、回测、更新）放 `wx.lib.newevent` + 后台线程，主线程只刷新 UI |

**备选**（如果你更看重开发速度/外观）：
- **PySide6**：控件更现代、样式更好调，但要新增一个较大的依赖。
- **本地 Web（FastAPI + 浏览器 或 Streamlit）**：开发最快、图表最好看，但严格说不算"桌面 UI"，且要常驻一个服务进程。

> ⚠️ **一个重要约束**：我这边运行在无显示环境的沙箱里，**无法看到窗口效果**，也无法验证布局美观度。
> 因此我会把 UI 拆成 **「视图模型层（纯数据、可无头测试）」+「wx 视图层（薄）」**：
> - 视图模型层（`quant/ui/viewmodels.py`）：所有取数、过滤、计算、导出逻辑，我用 pytest 保证正确；
> - 视图层：只做控件绑定与绘制，需要**你在本地运行**看效果、提修改意见。
> 这样即使我看不到界面，功能正确性仍然可验证。

**交互要点**
1. 条件用「复选框启用 + 参数框」的形式，未勾选的条件不参与过滤。
2. 每个条件就是 `quant/filter` 里的一个过滤器实例；页面右侧实时把当前条件翻译成等价命令行（方便复制）：
   `quant screen --filter exclude_st --filter pe:min=0,max=20 --filter pe_percentile:window_years=10,max=10 ...`
3. 运行后展示 `ScreenResult.steps`（每一步剔除多少）——这是复用已有能力。
4. **保存/载入方案**：条件列表序列化成 JSON（`~/.quant/screens/*.json` 或项目内 `config/screens/`）。
5. 结果表默认列：代码/名称/收盘/市值/PE/PB/PS/PE分位/ROE/负债率/单季营收同比；
   列可自定义勾选，可排序，双击进 P3。
6. 导出 CSV（`utf_8_sig`，Excel 直接打开），可选中文列名。

**性能预期**：估值分位走预计算表 → 毫秒级；技术类条件（突破均线等）需要读历史行情，
首次约 5~10 秒（`FilterContext` 已做缓存），页面显示"计算中…"。

## 6. 需要新增的底层能力（UI 的前置工作）

### 6.1 估值历史分位（需求 1.1 的核心）

**口径定义**（请确认，见 §9 问题 2）

- 对股票 s、交易日 t：
  `PE_t = close_org_t / eps_ttm(t)`；`eps_ttm(t)` 取 t 时点**已披露**的最近报告期的 TTM 值。
- **分位** = 窗口内 `PE < PE_t` 的交易日数 ÷ 窗口内有效交易日数 × 100。
  - 「PE 处于 10% 低位」= 分位 ≤ 10，即窗口内至少 90% 的交易日 PE 比现在高 —— 与你的描述一致。
- **有效交易日**：剔除 `PE ≤ 0`（亏损期）与 `eps_ttm` 缺失的交易日（建议，否则负 PE 会污染分位）。
- 窗口：默认 **10 年**，可选 3 / 5 / 10 / 全历史。历史不足时用全部可得数据，并在界面标注"窗口仅 X 年"。
- 同理计算 **PB 分位**（`close_org / bvps_ttm`）与 **PS 分位**（`market_cap / revenue_ttm`）。

**实现方案（不新增 1000 万行大表）**

1. 新增表 `valuation_percentile`：**一行一只股票 × 一个窗口**，列为
   `symbol, window_years, pe_pct, pb_pct, ps_pct, sample_days, current_pe, current_pb, current_ps, computed_at`。
   数据量约 4925 × 3 ≈ 1.5 万行，可忽略不计。
2. 新增命令 `quant rebuild-valuation [--windows 3 5 10] [--workers N]`：
   逐股票读取日线 + 财务指标 → 计算逐日 PE/PB/PS → 算各窗口分位 → 写入。
   预估 4925 只 × 每只 2 次索引查询 + pandas 计算 ≈ **10~20 分钟**（后台跑，可中断续跑）。
3. 新增快照列：`pe_pct_10y / pb_pct_10y / ps_pct_10y`（以及 3y/5y），供筛选器直接使用。
4. 个股页的**估值带/估值历史**图按需实时计算单只股票（每只 2 次查询，毫秒级）。

### 6.2 PS 指标

`PS = 总市值 / 营业总收入(TTM)`。营业总收入来自 `fundamental.total_revenue`（累计值），
按与 EPS 相同的 TTM 公式计算，落到 `fundamental.revenue_ttm`（顺带补 `net_profit_ttm`）。
需要先把 `fundamental` 更新到最新季度（§5 的建议）。

### 6.3 新增过滤器（对应需求 1.1 / 1.3）

| 过滤器 | 参数 | 说明 |
|---|---|---|
| `pe_percentile` | `window_years=10, min, max` | PE 历史分位区间（新） |
| `pb_percentile` | 同上 | PB 历史分位 |
| `ps_percentile` | 同上 | PS 历史分位 |

| `ma_align` | `periods=5,10,20` | 均线多头排列（新） |
| `gross_margin` | `min, max` | 毛利率区间（新） |

### 6.4 回测改造

- `BacktestResult` 增加：**净值曲线**（date/value 序列）、`annual_return`、`sharpe`、交易明细列表。
- 策略**参数化**：每个策略声明 `params_spec`（名称、类型、默认值、范围），UI 据此生成参数表单；
  现在 `ma_period`、买入阈值等都是硬编码。
- 基准对比：同区间「买入持有」净值曲线（已有数据，容易加）。
